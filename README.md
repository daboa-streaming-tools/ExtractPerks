# ExtractPerks

Dead by Daylight の「ロードアウト > インベントリ/パーク」画面のスクリーンショットから、
ひし形のパークアイコンを1つずつ切り出して透過PNGとして保存するツールです。

ゲームファイルには一切アクセスせず、ブラックボックスな処理もありません。中身が読める
PowerShellスクリプトが、すでに撮ってあるスクリーンショットからアイコンを切り出すだけです。
スクリーンショットさえ撮れれば、誰でも使えます。

**本格的な抽出ツールではなくこちらを使う理由**: バイナリからアセットを直接抜くような
本格的なツールが必要な方は、そちらの専用ツールを使うことをおすすめします。本ツールは
あえてその役割を狙わず、「スクリーンショットだけで完結し、ゲームファイルには一切触れない」
という立ち位置に絞っています。手元のロードアウトのアイコンがちょっと欲しい配信者さん向けの、
気軽なツールです。

## かんたん使い方ガイド(初めての方向け)

OBSの設定を自分でいじれるくらいの方であれば、下記の手順通りに進めれば使えます。
「ターミナル」や「PowerShell」に馴染みがなくても大丈夫です。

### 0. 事前準備: PowerShell 7 を入れる

動作確認は新しい黒いアイコンの **「PowerShell 7」** で行っています。
Windowsに最初から入っている青いアイコンの「Windows PowerShell」でも基本的に動きますが、
念のためPowerShell 7の利用を推奨します。

1. Microsoft Store を開き、「PowerShell」で検索してインストール
   (またはPowerShell公式サイトからダウンロードしてインストール)

### 1. ツール一式をダウンロードする

1. GitHubのページ右上あたりにある緑色の「Code」ボタン → 「Download ZIP」をクリック
2. ダウンロードした ZIP を右クリック →「すべて展開」で好きな場所(デスクトップなど)に展開

### 2. DBDのスクリーンショットを撮る

1. Steam経由でDBDを起動する(Steamオーバーレイが使える状態にしておく)
2. ロードアウト画面(パーク一覧が見える画面)で **F12キー** を押してスクリーンショットを撮る
3. 撮った画像は、Steamのスクリーンショット機能(Steam内「表示」→「スクリーンショット」)から
   「フォルダーで表示」を選ぶと、保存場所を開けます

### 3. スクリーンショットを src フォルダに入れる

1. 手順1で展開したフォルダの中にある `src` フォルダを開く
2. 手順2で撮った `.jpg` 画像をこのフォルダにコピーする

### 4. スクリプトを実行する

1. `ExtractPerks.ps1` があるフォルダを開く
2. フォルダ内の何もない場所を **Shift + 右クリック**
3. 出てきたメニューから「PowerShell ウィンドウをここに開く」または「ターミナルで開く」を選ぶ
   (見当たらない場合は、フォルダの上部のアドレスバーをクリックして `powershell` と入力しEnter)
4. 開いた黒い画面に次を貼り付けてEnterキー

   ```
   .\ExtractPerks.ps1
   ```

5. 初回だけ赤字のエラーが出た場合は、次を1回だけ実行してから、もう一度手順4をやり直してください

   ```
   Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
   ```

   (「実行しますか?」と聞かれたら `Y` と入力してEnter)

### 5. 完成したアイコンを確認する

- `out` フォルダを開くと、`0001.png`、`0002.png`…という連番で
  パークアイコン(背景透過PNG)が並んでいます
- 背景が透明なので、OBSの「画像ソース」やオーバーレイ素材としてそのまま使えます

### つまずきやすいポイント

| 症状 | 対処 |
|------|------|
| 右クリックしても「PowerShellウィンドウをここに開く」が出てこない | Windows 11なら「ターミナルで開く」を探す。それも無ければアドレスバーに `powershell` と入力してEnter |
| 実行時に赤字でエラーが出て止まる | 上記手順4-5の `Set-ExecutionPolicy` を実行してから再実行 |
| 文字化けした変なエラーが出る | 黒いアイコンの「PowerShell 7」から実行しているか確認(通常のPowerShellでも動作する想定ですが、念のため) |
| `out`フォルダに何も出てこない、少ない | `src`フォルダに画像がちゃんと入っているか、スクショの解像度が1920×1080か確認 |

## 必要環境(技術詳細)

- Windows + PowerShell 7以降(pwsh)を推奨
  - スクリプトはBOM付きUTF-8で保存しているため、Windows PowerShell 5.1(`powershell.exe`)でも
    日本語コメントの文字化けは基本的に発生しませんが、動作確認は `pwsh` で行っています
- 追加インストール不要(.NET の `System.Drawing` のみ使用)

## 実行方法(コマンド一覧)

```bash
cd D:\ExtractPerks #実際のパスに合わせてください
.\ExtractPerks.ps1
```

`src` フォルダ内の `*.jpg` を全て処理し、`out` フォルダに `0001.png` から連番で保存します。

再実行時に古い出力を残したくない場合は、事前に `out` フォルダを空にしてください。

```bash
cd D:\ExtractPerks

.\ExtractPerks.ps1
```

初回実行時に実行ポリシーのエラーが出た場合は、以下を一度だけ実行してから再度試してください。

```bash
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

## 対応入力ファイルの仕様

このスクリプトは画像の内容を解析してひし形を検出しているわけではなく、
**固定座標での切り抜き**を行っています。そのため、入力画像は以下の条件を
満たしている必要があります。

- 解像度: **1920×1080**
- Steamの標準スクリーンショット(F12キー)で撮影したもの
- 画面: DBDの「ロードアウト」画面で、左側に「インベントリ/パーク」の
  5列×3段(最大15個)のひし形グリッドが表示された状態
  - UIの拡大率やレイアウトが変わると座標がずれるため、上記以外の解像度・
    UIスケールのスクリーンショットには対応していません
- ファイル形式: `.jpg`
- ファイル名: アルファベット順に並べたときに撮影日時順になっていること
  (例: `20260821125444_1.jpg` のような日時ベースのファイル名。
  Steamの標準スクリーンショット機能で撮ったファイルはこの形式になります)

対応していない画像(解像度違いなど)を混ぜると、ひし形以外の場所を
切り抜いてしまうので注意してください。

### 動作確認済みのDBDグラフィック設定

DBD本体の「設定 > グラフィック > 動画」で、以下の設定で撮影したスクリーンショットで
動作確認しています。異なる設定にすると解像度やUIレイアウトがずれ、正しく切り抜けない
場合があります。

| 設定項目 | 値 |
|---|---|
| フルスクリーンモード | ウィンドウ |
| 画面の解像度 | 100% |
| 画面サイズ | 1920×1080 |
| 16:9のアスペクト比 | オフ |
| 自動調整 | オフ |

## 処理の仕組みと座標の算出方法

### 1. ひし形グリッドの座標(固定値)

対象のインベントリグリッドは、1段目・3段目と2段目で横方向に半ピッチずれた
千鳥配置になっています。各ひし形の中心座標(x, y)と半径(中心から頂点までの
距離)は、実際のスクリーンショットを1px単位でスキャンして求めた実測値を
スクリプト内にハードコードしています。

| 段 | X座標(5列) | Y座標 | 備考 |
|----|--------------|-------|------|
| 1段目 | 395, 519, 642, 768, 890 | 632 | |
| 2段目 | 457, 581, 704, 829, 952 | 726 | 半ピッチ右にずれた千鳥配置 |
| 3段目 | 395, 519, 642, 768, 890 | 819 | 1段目と同じX |

半径(`$Radius`)は58px(ひし形の中心から頂点までの距離)。

座標の求め方: 中心を通る横/縦の走査線上で、背景色(グレー~暖色系)から
ひし形の黒枠(輝度が急に下がる)への変化点を検出し、その中間点を中心座標
としました。複数の列・複数のスクリーンショットで再現性を確認済みです。

**もし将来UIの解像度やレイアウトが変わった場合**は、`ExtractPerks.ps1` 冒頭の
`$Row1X` / `$Row2X` / `$Row3X` / 各段のY座標 / `$Radius` をこの手順で
測り直す必要があります。

### 2. 空きスロットの判定

15枠のうち、パークを所持していないページでは一部が空(輪郭だけの「+」)に
なります。これを誤って切り出さないよう、各ひし形の内部を密にサンプリングし、
「紫色(R・BがGより明確に高い色)の画素が10個以上あるか」で
埋まっている/空いているを判定しています(`Test-SlotFilled` 関数)。
したがって、パークの背景色が紫以外（黄色や緑など）の場合は正しく判定できません。

### 3. ひし形の外側の透過

中心からのオフセット `(dx, dy)` について `|dx| + |dy| > 半径` となる画素は
ひし形の外側とみなし、透明(alpha = 0)にします。

### 4. 背景(紫色・黒枠)の透過

`$RemoveBackground = $true`(デフォルト)の場合、ひし形の内側もさらに
輝度で判定し、白いアイコン線画だけを残します。

```powershell
$LumaLow = 140
$LumaHigh = 220
```

- 輝度が `$LumaLow` 以下 → 完全透明
- 輝度が `$LumaHigh` 以上 → 完全不透明
- その間はグラデーションで半透明(線の縁のアンチエイリアスを滑らかにするため)

紫のにじみが気になる場合は `$LumaLow` を上げる、線が細く/かすれて
見える場合は下げる、で調整してください。

`$RemoveBackground = $false` にすると、ひし形の外側だけ透過にして、
内側の紫背景・黒枠・アイコンはそのまま残します。

### 5. 「爪痕」装飾の除外

ひし形の右肩には、所持しているパークすべてに共通する固定装飾(3本の
白い爪痕のようなマーク)が乗っており、輝度だけでは背景と区別できないため
別途、中心からの相対座標で除外領域を指定しています(`$ClawExclusionBoxes`)。
この座標も、複数の異なるアイコンを比較して装飾だけに共通する画素を
特定する方法で実測しました。

## 出力

- `out/0001.png`, `out/0002.png`, ... という連番ファイル
- サイズはひし形の外接正方形(116×116px = 半径58×2)
- 通し番号は「`src`内のファイル名の昇順」→「グリッド内の並び順(1段目左から
  右、2段目、3段目)」の順に振られます
- PNG(アルファチャンネル付き)

## トラブルシューティング

| 症状 | 原因・対処 |
|------|-----------|
| スクリプト実行時に文字化けした構文エラーが出る | `pwsh`(PowerShell 7)から実行する。改善しない場合はファイルがUTF-8(BOM付き)で保存されているか確認 |
| 出力枚数が想定より少ない/多い | 空きスロット判定のしきい値(`Test-SlotFilled` 内の `$hits -ge 10`)を調整 |
| ひし形がずれて切り抜かれる | 入力画像の解像度・UIレイアウトが前提と異なっていないか確認。異なる場合は上記「座標の求め方」を参考に座標を測り直す |
| 紫色が残る/線が薄くなりすぎる | `$LumaLow` / `$LumaHigh` を調整(上記4節を参照) |
